# FleurTerm Tabby 风格 UI 设计规格

日期：2026-07-17

## 1. 背景

FleurTerm 当前界面以紫蓝渐变、大圆角卡片和独立品牌标题栏为主要视觉特征，与产品设计文档要求的“终端优先、高信息密度、低装饰”方向不一致。

本次改造以用户提供的 Tabby Alpha 截图和本机 Tabby 的界面层次为视觉参考，重组 FleurTerm 的窗口框架、欢迎页、终端工作区和设置页。改造只借鉴布局语言、色彩层次和交互密度，继续使用 FleurTerm 自有名称、图形与文案，不复制 Tabby 的商标、Logo、图标素材或源代码结构。

## 2. 目标

- 将现有窗口改造成紧凑的 Tabby 式标题栏、标签栏和内容区结构。
- 使用中性炭黑、低饱和灰和浅青蓝构成统一的深色视觉系统。
- 新增完整的欢迎页入口布局，包括暂未实现的配置、连接和最近连接入口。
- 新增可进入的设置页面，完成分类导航和表单控件的展示效果。
- 保持现有本地终端、标签页和分屏能力可用。
- 默认使用完全不透明的窗口与表面颜色。

## 3. 非目标

- 本次不实现 SSH 连接、连接配置、最近连接数据或 AI 能力。
- 本次不保存或应用设置页中的控件值。
- 本次不实现窗口透明度效果；设置页只展示透明度控件，默认值为 100%。
- 本次不修改终端后端协议和 Rust 进程管理逻辑，除非前端适配出现无法绕开的编译问题。
- 本次不逐像素复制 Tabby，也不引入 Tabby 品牌资产。

## 4. 信息架构

应用包含三种主要界面状态：

1. 欢迎页：没有活动终端时显示品牌标识和快捷入口。
2. 终端工作区：存在活动终端时显示标签、分屏终端和状态栏。
3. 设置页：从欢迎页或顶部菜单进入，显示左侧分类和右侧静态表单。

欢迎页和设置页属于前端展示层。设置页的打开、返回和分类切换正常工作，但控件修改不写入配置，也不触发后端行为。

## 5. 窗口框架

### 5.1 标题栏

- 使用约 36px 高的紧凑标题栏。
- macOS 下为窗口交通灯保留安全区域。
- 移除现有独立的 54px FleurTerm 品牌 Header。
- 标题栏只保留必要的应用菜单、当前上下文和窗口拖动区域。
- 背景使用不透明实色，不启用毛玻璃、透视或背景模糊。

### 5.2 标签栏

- 标签栏高度约 36–38px，与标题栏形成连续的深色窗口框架。
- 活动标签通过轻微的表面层级变化和浅青蓝细线识别。
- 标签关闭按钮默认弱化，悬停标签或聚焦时提高对比度。
- 新建终端入口使用紧凑图标按钮，不再使用紫色渐变主按钮。
- 标签过多时保持现有滚动或收缩能力，不增加大面积装饰。

### 5.3 内容区与状态栏

- 内容区直接承载欢迎页、终端或设置页，不使用独立的大圆角外卡片。
- 终端分屏之间保留 1–3px 分隔线。
- 终端背景与承载面板保持相同色阶，降低卡片感。
- 状态栏高度约 28px，使用不透明深色背景。

## 6. 视觉系统

### 6.1 基础色板

| 用途 | 颜色 |
| --- | --- |
| 主画布 | `#202222` |
| 标题栏和标签栏 | `#292b2b` |
| 抬升表面与悬停层 | `#303232` |
| 输入框 | `#181a1a` |
| 主文字 | `#d7d7d3` |
| 次要文字 | `#999b97` |
| 强调色 | `#8fd8e8` |
| 默认边框 | `rgba(255, 255, 255, 0.10)` |

以上颜色是实现基线。允许在浏览器和桌面端视觉校验时做小幅明度调整，但不得重新引入紫色渐变、霓虹发光或高饱和大色块。

### 6.2 形状与动效

- 普通控件圆角限制在 4–6px。
- 终端面板和普通按钮不使用明显阴影。
- 阴影仅用于需要表达浮层关系的菜单或弹出层。
- 常规悬停和页面切换过渡约为 120ms。
- 遵循系统的减少动态效果偏好。

### 6.3 不透明度原则

- 默认窗口、标题栏、标签栏、欢迎页、终端区和状态栏全部使用实色背景。
- 透明度只能由未来的设置功能主动开启。
- 当前设置页展示透明度为 100%，但不应用或保存该值。

## 7. 欢迎页

- 内容在主区域水平和垂直方向居中，主体宽度约 340px。
- 顶部使用 FleurTerm 自有的终端符号和产品名称。
- 下方使用 Tabby 式紧凑纵向入口列表，展示：
  - 配置和连接；
  - 新建终端；
  - 最近连接；
  - 设置。
- “新建终端”沿用现有真实能力。
- “设置”打开本次新增的设置页面。
- “配置和连接”和“最近连接”本次只展示外观，不执行功能。
- 未实现入口不显示“即将推出”等开发状态文案。
- 不使用 Tabby Logo、Tabby 名称或其专有插画。

## 8. 终端工作区

- 保留现有终端创建、关闭、标签切换和分屏行为。
- 将当前圆角卡片式终端容器改为与窗口内容区融合的平面结构。
- 聚焦终端通过细边框或强调色细线表达，不使用大面积高亮。
- xterm 背景与终端容器颜色一致。
- 滚动条保持低对比度，悬停时提高可见性。
- 状态信息使用次要文字颜色，仅错误或异常状态使用语义色。

## 9. 设置页

### 9.1 页面结构

- 设置页占据主内容区。
- 左侧为固定宽度的分类导航，右侧为可滚动的设置表单区域。
- 页面提供清晰的返回入口，可回到进入设置前的欢迎页或终端工作区。
- 设置页沿用相同的不透明深色视觉系统。

### 9.2 分类

首批展示以下六类：

- 通用；
- 外观；
- 终端；
- 配置和连接；
- 快捷键；
- AI。

分类切换属于展示交互，需要正常更新右侧内容。

### 9.3 静态控件

- 右侧可展示开关、下拉框、输入框、颜色选择、字体选择和范围滑块等控件。
- 外观分类包含主题、字体和窗口透明度，其中透明度显示为 100%。
- 控件不显示开发提示，也不需要保存或应用值。
- 为避免产生错误状态，本轮控件可保持只读展示；分类导航和页面返回仍可操作。

## 10. 响应式与可访问性

- 在常见桌面窗口宽度下保持左侧设置导航和右侧表单布局。
- 窄窗口下允许设置导航缩窄，但不得遮挡返回入口和主要字段。
- 所有可操作入口提供键盘焦点样式，焦点色使用浅青蓝强调色。
- 图标按钮必须具备可访问名称或提示文本。
- 主文字、次要文字和控件边界需要保持足够对比度。
- 不只依赖颜色区分活动标签、选中分类或禁用状态。

## 11. 前端状态边界

- 现有终端状态继续由当前状态管理模块负责。
- 新增的页面状态只包含当前主界面和当前设置分类。
- 不为静态设置控件引入持久化存储、Tauri 命令或后端模型。
- 未实现的欢迎页入口不创建伪数据或模拟连接流程。

## 12. 验收标准

- 启动应用后，欢迎页在颜色、密度和布局层级上与用户提供的 Tabby Alpha 参考风格一致。
- 窗口默认完全不透明。
- 现有紫色径向背景、紫色渐变主按钮和大圆角卡片视觉已移除。
- 顶部采用紧凑标题栏与标签栏结构，并为 macOS 交通灯保留空间。
- 欢迎页展示约定的四类入口，其中新建终端和设置入口可以正常进入对应页面。
- 设置页展示六个分类，分类导航和返回操作正常，控件不保存或应用配置。
- 本地终端、标签切换、关闭终端和分屏能力未回归。
- 欢迎页和设置页不包含 Tabby 商标或原始品牌素材。
- 前端测试、类型检查、代码规范检查和生产构建通过。
- Tauri 调试构建通过，并完成欢迎页、终端标签、分屏和设置页的桌面视觉检查。
