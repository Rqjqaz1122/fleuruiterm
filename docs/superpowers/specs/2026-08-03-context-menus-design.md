# FleurTerm 全局右键菜单设计

## 目标

为 FleurTerm 增加统一的自定义右键菜单，并根据用户点击的页面与具体目标展示不同操作。菜单必须支持现有中英文切换、键盘操作、窗口边缘定位和 disabled 状态，同时复用各页面已有业务能力，不改变原有确认流程。

## 交互范围

### 终端

- 有选区时允许复制，没有选区时禁用复制。
- 提供粘贴、全选和清空终端。
- 清空动作调用现有终端清理能力，不直接操作 DOM。

### 标签栏

- 标签项提供新建终端、关闭当前标签和关闭其他标签。
- 不可关闭的应用标签不显示关闭操作。
- 标签栏空白区域只提供新建终端。

### AI 对话

- 消息区域提供复制所选内容、复制当前消息和清空对话。
- 对话空白区域提供清空对话；无消息时禁用该操作。
- AI 输入框及其他可编辑控件使用统一编辑菜单：剪切、复制、粘贴、全选。

### SFTP

- 文件提供下载、复制远程路径和删除。
- 目录提供打开、复制远程路径和删除。
- 列表空白区域提供上传、刷新和返回上级目录。
- 删除继续调用现有删除请求，并由现有确认弹窗进行二次确认。
- 传输或加载期间，根据现有 busy 状态禁用冲突操作。

### 首页与设置页

- 首页提供新建终端和打开设置。
- 设置页中的输入控件使用统一编辑菜单，其他区域提供新建终端。

## 架构

新增一个全局 `AppContextMenu` 组件负责菜单渲染、定位、焦点移动和关闭行为。菜单项使用带判别字段的 TypeScript 模型描述 label、enabled、separator 和 action，业务组件只负责将当前点击目标转换为菜单项，不把页面业务判断放入菜单组件。

`App.vue` 挂载唯一菜单实例，并通过一个轻量的 context-menu service 接收页面发出的打开请求。终端、标签、AI、SFTP、首页和设置组件在最接近业务目标的位置处理 `contextmenu` 事件，以保留必要的 session、tab、message 或 entry 信息。输入框由 service 识别 `input`、`textarea` 和 `contenteditable`，优先生成编辑菜单。

## 行为与定位

- 阻止应用区域内浏览器默认右键菜单。
- 菜单先按指针位置打开，再根据实际尺寸向左或向上修正，避免超出可视窗口。
- 点击菜单外部、页面滚动、窗口 resize、窗口失焦或按 `Escape` 时关闭。
- 支持方向键移动焦点、`Home`、`End`、`Enter` 和 `Space` 执行操作。
- 执行操作后立即关闭；失败由现有页面错误状态或通知机制展示。
- 菜单使用现有颜色 token，保持紧凑、低光泽的终端风格。

## 国际化

所有菜单 label 进入现有 `src/i18n/locale.ts`，中文和英文键必须同时提供。业务对象名称和远程路径保持原值，不进行翻译。

## 剪贴板

普通输入控件优先调用浏览器支持的编辑命令，以保留选区和光标位置。终端和业务文本复制使用 Clipboard API，并对不可用环境进行安全降级。远程路径复制只复制完整 path，不附加额外说明。

## 测试边界

- 菜单组件：定位修正、disabled、separator、关闭条件和键盘操作。
- 菜单 service：不同目标模型、编辑控件识别和单实例状态。
- 页面集成：终端、标签、AI、SFTP、首页和设置页分别验证菜单项与既有事件的映射。
- 国际化：确保新增 key 在中文和英文中完整存在。

## 非目标

- 不使用 Tauri native context menu。
- 不新增可配置的右键菜单设置。
- 不改变 SFTP 删除确认、终端关闭和 AI 对话存储的既有业务规则。
- 不控制或启动桌面应用，交互效果由用户自行验证。
